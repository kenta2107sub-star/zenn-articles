## つくったもの

Claudeデスクトップアプリの入力欄で `/` を打つと、スラッシュコマンドの一覧と日本語の説明を画面右下にポップアップ表示するmacOSアプリです。

https://github.com/kenta2107sub-star/claude-skill-jp-helper

![Claudeアプリの入力欄で / を打つと、コマンド一覧と日本語の説明がポップアップで表示される様子](/images/claude-slash-command-jp-helper/popup-preview.png)

- `/` だけを打つと、81個のコマンドを7つのカテゴリに分けて一覧表示
- `/cl` のように続けて打つと、前方一致で候補を絞り込み
- 候補にマウスを乗せると、詳しい説明と使用例を表示

## なぜ作ったか

Claudeアプリで `/` を打つと、コマンドの候補が出てきます。
ただ、出てくるのは英語のコマンド名と英語の説明文で、読んでも中身がつかめないことがよくありました。

たとえば `/new` と `/clear` は、名前だけ見ると別の機能に思えます。
実際は `/new` が `/clear` の別名で、どちらを押しても新しい会話が始まります。
`/checkpoint` と `/rewind` も同じ関係です。
こうした関係は、候補に出る英語の短い説明からは分かりませんでした。

そこで、Claudeアプリが出す候補の横に、日本語の説明を並べて出すことにしました。
辞書は自分で書くので、別名かどうかや、どんな場面で使うかまで説明に書き込めます。

## 技術構成

- Electron 28 ＋ TypeScript
- `uiohook-napi`：OS全体のキー入力を拾うグローバルキーフック
- `data/commands.json`：コマンド辞書
- Jest ＋ ts-jest：辞書検索のユニットテスト

この構成になったのは、Claudeアプリの中には手を入れられないからです。
入力欄を外から監視したり、UIを差し込んだりする拡張の仕組みが用意されていません。
そのため、アプリの外側でキー入力を拾い、別のウィンドウを重ねて出す形にしました。

表示位置は、入力欄の近くではなく画面右下に固定しています。
入力欄の近くには、Claudeアプリ自身の `/` の候補が出ます。
そこに重ねると、二つの一覧が被って両方とも読みにくくなります。

## 仕組み

`/` を打ってからポップアップが出るまでの流れは次のとおりです。

1. `uiohook-napi` でOS全体のキーダウンを受け取る。コールバックが長引くとOSがフックを止めるので、中では必要な値だけを写し、処理は `setImmediate` で後ろに回す
2. `/` が押された瞬間に、`lsappinfo` で前面アプリのバンドルIDを調べる。Claudeアプリ（`com.anthropic.claudefordesktop`）のときだけ入力の追跡を始める
3. 続けて打たれた文字を追跡中の文字列に足し、`commands.json` を前方一致で検索する
4. 候補があれば、画面右下の透明なウィンドウに一覧を出す。スペース、Enter、Esc、クリック、Claudeアプリ以外への切り替えで閉じる

ポップアップのウィンドウは `focusable: false` にして、`showInactive()` で出しています。
入力中のClaudeアプリからフォーカスを奪うと、打った文字がClaudeアプリに届かなくなるためです。
隠すときもウィンドウは閉じず、透明度を0にするだけにしています。
`/` を打つたびにウィンドウを作り直すと、描画の分だけ表示が遅れます。

前面アプリの確認は、追跡中は100ミリ秒ごと、それ以外は1秒ごとに回しています。

![Claudeアプリの横に、画面右下のポップアップが出ている実際の画面](/images/claude-slash-command-jp-helper/screen-popup.png)

要するに、Claudeアプリには一切触れず、OSのキー入力と前面アプリの情報だけで「いまClaudeアプリに `/` が打たれている」ことを判断しています。

## 使い方

```bash
git clone https://github.com/kenta2107sub-star/claude-skill-jp-helper.git
cd claude-skill-jp-helper/electron
npm install
npm run build
npx electron .
```

動かすには、macOS 13以降とNode.js 18以降が要ります。
キー入力を拾うため、システム設定の「プライバシーとセキュリティ」から、起動に使うターミナルに**入力監視**の権限を付けてください。
辞書の `data/commands.json` はビルドの対象外なので、編集したらアプリを再起動するだけで反映されます。
ログイン時の自動起動の設定など、詳しい手順はREADMEにまとめています。

## つまずいたところ

### ホバーしていないのに残るツールチップの枠

一番時間を取られたのが、マウスを乗せていないのにツールチップの枠だけが見える不具合です。

最初はCSSの問題だと考えていました。
非表示のクラスが `visibility: hidden` になっていて、ツールチップの150ピクセル分の領域が残っていたからです。
`display: none` に変えれば領域ごと消えます。
その2分後には、ツールチップが消えたときに一覧が上にずれる問題も `justify-content: flex-end` で直しました。

ところが2日後、同じ症状がまた出ました。

**原因はCSSではありませんでした。**
ポップアップを隠す処理は、ウィンドウの透明度を0にするだけで、中の画面（レンダラー）には何も伝えていませんでした。
そのためツールチップは表示中の状態のまま残り、次に透明度が1に戻った瞬間、ホバーしていないのに枠が見えていました。

直し方は、一覧を送る前に「ツールチップを閉じる」という通知をIPC（プロセス間通信）で送り、画面側の状態を戻してから表示することです。
ウィンドウを閉じずに透明度で隠す設計にした時点で、メインプロセス（ウィンドウを操作する側）の「隠した」と画面側の「隠れている」がずれる余地ができていました。

### 前面のアプリがClaudeアプリかどうかの判定

グローバルキーフックはOS全体のキー入力を拾うので、そのままだとブラウザで打った `/` にも反応します。
そこで、前面のアプリがClaudeアプリかどうかを別の手段で確かめる必要がありました。

macOSでこれを調べる定番は `osascript` です。
ところが、ログイン時に自動起動させるLaunchAgentから動かすと、権限エラーで空文字が返ってきました。
代わりに使ったのが `lsappinfo` で、`lsappinfo front` で前面アプリの番号を取り、その番号からバンドルIDを引いています。

## 作ってみて

普段の業務はJava/Spring BootのバックエンドとReact/Next.jsのフロントエンドで、権限やフォーカスはブラウザやフレームワークが面倒を見てくれます。
今回は、そこを全部自分で相手にすることになり、OSの挙動に振り回されました。

入力監視の権限は、アプリのフォルダを移動したり名前を変えたりすると外れます。
キーフックは、OS側のタイムアウトで無効化されると、アプリが生きたままキー入力だけが届かなくなります。
どちらもエラーは出ず、ポップアップが出ないという症状しか見えません。
後者には、エラー出力を監視してフックを張り直す仕組みを後から足しました。

いまは `/checkpoint` にマウスを乗せると「/rewind のエイリアス」と出ます。
英語の説明を読み解かなくても、どちらを押せばいいかがその場で分かります。
