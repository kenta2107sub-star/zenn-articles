> 検証日: 2026-10-08（検出コマンドの動作を再確認）／ Claude Code 2.1.270 ／ macOS 13.7.8

macOSで、濁点や半濁点を含む日本語のフォルダの下でClaude Codeを使うと、同じプロジェクトの履歴が2つのディレクトリに割れることがあります。
割れた片方は `/resume` に出てこないので消えたように思えますが、ファイルは `~/.claude/projects/` に残っています。
原因は、同じ「ダ」がUnicodeの正規化の形によって1文字にも2文字にも数えられることでした。

以下の数字は、2026-09-07 に行ったClaude Codeの環境の監査で得たものです。

## 何が起きたか

監査の途中で `~/.claude/projects/` を一覧にしたとき、ほとんど同じ名前のディレクトリが2つ並んでいることに気づきました。

```
-Users-<user>-Desktop--------Claude---------obsidian-claude-pkm   28セッション
-Users-<user>-Desktop---------Claude----------obsidian-claude-pkm  5セッション
```

違うのはハイフンの本数だけです。
どちらも、デスクトップの「作業フォルダ」の下にある同じプロジェクトを指しています。
セッションの履歴は28件と5件に分かれていて、`/resume` に出てくるのは片方だけでした。

対はこの1組だけではありませんでした。
一覧全体を見直すと、38のディレクトリのうち10組が同じように対になっていました。
小さい側を合わせると152MBあり、そのぶんの履歴が `/resume` から見えなくなっていました。

## どう測ったか

まず、対になっているディレクトリを機械的に拾いました。
ディレクトリ名に続くハイフンを1本に潰すと、割れた2つは同じ名前になります。
そこで、潰したあとに重複する名前だけを出しました。

```
ls ~/.claude/projects | sed 's/-\{2,\}/-/g' | sort | uniq -d
```

これで10組が出ました。

次に、Claude Codeが覚えているプロジェクトの一覧を見ました。
`~/.claude.json` の `projects` には、同じパスがNFCとNFDの両方の形で9件登録されていました。
画面の上では同じ文字列なのに、Claude Codeは別のパスとして記録していたことになります。
対になったディレクトリの10組と1件合わない理由は、確かめていません。

最後に、小さい側に何が残っているかを確かめました。
NFD側のファイル16件を、NFC側の同名ファイルと突き合わせると、13件（144MB）はNFC側に中身がそっくり含まれていました。
NFD側にしか無かったのは3件だけです。
13件がすでにNFC側にあったのは、後で述べる同期のスクリプトが動いていたからだと考えています（確かめてはいません）。

## 原因

`~/.claude/projects/` のディレクトリ名は、作業フォルダの絶対パスの英数字以外を、1文字につき1本のハイフンに置き換えて作られます。
`/` も日本語も、1文字なら1本です。

ここで、濁点や半濁点を含む文字は、Unicodeの正規化の形によって文字数が変わります。
**NFC**（合成済みの1文字で表す形）では「ダ」は1文字です。
**NFD**（基底の文字と結合用の濁点に分ける形）では、「タ」と結合用の濁点の2文字になります。
「プ」も同じで、NFCでは1文字、NFDでは「フ」と結合用の半濁点の2文字です。

そのため「作業フォルダ」は、NFCで6文字、NFDで7文字になります。
「キャリアプラン」はNFCで7文字、NFDで8文字です。
文字数が1つ違えばハイフンも1本違い、名前の違う別のディレクトリができます。

割れた場所も、濁点の有無とそろっていました。
同じ監査で見たフォルダのうち、割れていたのは「作業フォルダ」と「キャリアプラン」の下だけです。
濁点を含まない「個人開発」の下は、NFCでもNFDでも同じ文字列になるので、割れていませんでした。
英数字だけのパスなら、この分裂は起きません。

`/resume` が片方しか出さないのは、今いるパスの正規化の形に合うディレクトリだけを見ているからだと考えています。
ただ、これは推測で、Claude Codeの実装を確かめたわけではありません。
確かめたのは、片方しか一覧に出ないという結果のほうです。

## どう直したか（直せなかったか）

先に入れたのは、割れ続けても困らないようにする応急処置でした。
中身が完全な側のファイルを、`/resume` に出る側へコピーするスクリプトを書き、LaunchAgentで30分ごとに走らせています。
上書きするのは、上書き先の中身が上書き元の先頭と完全に一致するときだけです。
このため、上書きで失われる内容はありません。
上書き前のファイルも `.bak` として残しています。

そのうえで、10組を次の順で1つずつまとめました。

1. NFD側の各ファイルについて、NFC側の同名ファイルがその中身で始まっているかを確かめる。始まっていれば消してよい
2. NFC側に無いファイルだけをコピーし、バイト単位で一致するかを確かめる
3. すべてのファイルがNFC側に含まれることを確かめ直してから、NFD側のディレクトリを消す

これで、対になったディレクトリは0組になりました。

この途中で、もう1つつまずきました。
消す前の退避用に、NFD側のディレクトリを `tar czf out.tgz <dir>...` でまとめようとしたところ、失敗しました。
`~/.claude/projects/` のディレクトリ名はハイフンで始まるので、相対パスで渡すと `tar` がオプションとして解釈します。
`-C <親>` で親ディレクトリに移るだけでは防げず、`-T <リスト>` で対象をファイルから読ませ、リストの各行の先頭に `./` を付けて解決しました。

手を付けなかったところもあります。
`~/.claude.json` に残っているNFD側の9件の登録は消していません。
このファイルは動いているセッションが書き込むので、外から編集すると書き込みとぶつかるからです。
残しておいても実害はありませんでした。

## 残っている疑問

片付けたのは割れた結果で、割れる原因はまだ止めていません。
NFD側のディレクトリには、最終更新が監査の数日前のものもありました。
今も新しく割れ続けている可能性があります。

どのツールがNFDのパスを書いているのかも分かっていません。
Claude CodeのCLIとDesktopアプリのどちらなのか、あるいは起動の仕方によるのかは未確認です。
切り分けるなら、濁点を含むフォルダで片方だけを使ってセッションを1つ作り、上の `uniq -d` の1行で新しい対が出るかを見るのが手早いと思います。

片付けた今も、最初に見つけた5セッションがどの経路でNFDの側に書かれたのかは分かっていません。
フォルダ名に濁点や半濁点があるなら、上の1行で対が出ないかを一度見ておけば、`/resume` に出てこない履歴に早く気づけます。
