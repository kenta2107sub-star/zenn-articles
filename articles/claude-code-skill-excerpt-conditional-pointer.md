> 観測日: 2026-09-01、2026-09-08 ／ 記事の作成: 2026-11-20（Claude Code 2.1.270、macOS 13.7.8）

この記事で分かること

- 10KB を超える規範ファイルを、全文を読ませずに Claude Code の返答へ効かせる手順
- 抜き書きから外すべき条項の見つけ方
- 残りの本文を、決まった条件のときだけ読ませる書き方

対象の読者: 文章の規範や設計の規約を Claude Code のスキルで持っていて、毎回効かせたいがコンテキストの量が気になっている人

大きな規範ファイルは、全文を常に読ませるより、効く条項だけを抜き書きして、本文は条件付きで読ませるほうが軽く済みます。
私の環境では、20,439 bytes のスキルから2,441 bytes を抜き書きして CLAUDE.md に入れました。
同じ形で、17,010 bytes の別のスキルからは約3.3KB を抜き書きしました。
手順は3つで、そのうち1つは、手元の決まりとぶつかる条項を外す作業です。

## 困っていたこと

2026-09-01、日本語の技術文章の規範を書いたスキル（20,439 bytes）を、Claude Code のすべての返答に効かせたいと考えました。
最初に浮かんだ案は2つです。

1つめは、全文を常に読ませる案です。
CLAUDE.md を4,953 bytes 減らせる代わりに、20,439 bytes を毎回読むことになります。
差し引きで15,500 bytes 増え、トークンも増えます。

2つめは、CLAUDE.md に「毎回このスキルを呼ぶ」と書く案です。
こちらは、呼ぶかどうかが Claude の判断に任されます。
CLAUDE.md はシステムプロンプトに入るので必ず読まれますが、Skill の呼び出しは保証されません。

どちらの案も、毎回効くことと軽いことを両立できませんでした。

## 抜き書きと条件付きの参照

そこで、全文の代わりに効く条項だけを CLAUDE.md へ写す形にしました。
2回目には、残りの本文を決まった条件のときだけ読ませる一節も足しました。
形は次の2つの部品からなります。

- **抜き書き**：規範ファイルから、効かせたい場面で使う条項だけを写したもの
- **条件付きの参照**：本文を読むべき場面を、数えられる条件で書いた一節

抜き書きは必ず読まれる場所に置きます。
条件付きの参照は、その条件に当たったときに本文を読ませるための一節です。

配布元のスキルの原文には手を入れません。
個人の書式を書き足すと、配布元が更新されたときに差分を取り込めなくなるからです。

## 抜き書きの手順

2回の抜き書きで、どちらにも効いた手順は次の3つです。

1. 適用する対象を先に分ける
2. 手元の決まりとぶつかる条項を洗い出して外す
3. 抜き書きを置く先が、必ず読まれる場所かを確かめる

### 適用する対象を先に分ける

最初に、その規範をいつ効かせるのかを決めます。
1回目は「常にか、場面を限るか」で分けました。
2回目は「読み物の記事か、手順の記事か」で分けました。

2回目に扱ったのは、文章に緩急をつけるための規範（17,010 bytes）です。
これを、記事の下書きを点検するスキルに効かせました。
読み物の記事でだけ使う規範なので、手順の記事には当てない、と先に決めています。
手順の記事は、読者が必要な箇所だけ拾って離れる読まれ方が正しく、読み進める推進力を求めると記事を悪くするからです。

点検用のスキルには、記事の種類ごとに緩急の点検を当てるかどうかを次のように書いています。

| 種類 | 見分け方 | 緩急の点検 |
|---|---|---|
| 読み物系 | 体験記、考察、解説エッセイ、技術書の章 | 当てる |
| 手順系 | チュートリアル、ハンズオン、セットアップ、リファレンス | 当てない |
| 混合 | 前半が背景説明で、後半が手順 | 読み物の節だけ当てる |

種類は、本文から次の順で決めます。

1. コードブロックと箇条書きが本文の半分以上を占めるなら手順系
2. 見出しが「〜する」「〜をインストール」など操作の連なりなら手順系
3. どちらでもなければ読み物系

### ぶつかる条項を外す

規範ファイルには、手元の決まりと逆を言う条項が混ざっています。
実際に外した条項は次の2つです。

- 規範の「結論を最後に一度だけ置く」は、CLAUDE.md の「結論を最初に書く」とぶつかる
- 規範の「太字を多用しない」は、絵文字やラベル行を積極的に使う手元の方針とぶつかる

1回目は、148行から25項目を拾い、私の判断で6項目を外し、最後は16項目、2,441 bytes にまとめました。

### 置く先を確かめる

抜き書きの置き先は、必ず読まれる場所にします。
1回目は CLAUDE.md に置きました。
2回目は、点検用のスキルに新しい分類（緩急の点検）として約3.3KB を足しました。
点検用のスキルは、9.1KB から14,012 bytes になりました。

## 条件付きの参照の書き方

2回目の点検用のスキルには、本文を読む条件を次のように書きました（スキルのパスは伏せています）。

```markdown
#### 本文を参照する条件

次のいずれかに当てはまるときだけ `<緩急の規範のSKILL.md>` を読んでから修正案を書く。

- このカテゴリの🟡以上の指摘が3件以上になった
- 修正案の文体設計（拍の作り方・緊張の張り方）まで書くようユーザーに求められた

2件以下なら上の確認項目だけで指摘を書き、本文は読まない。
```

条件は「3件以上」のように数えられる形で書きます。

参照の連鎖にも気をつけます。
緩急の規範は冒頭で日本語の技術文章の規範を読むよう指示していて、両方を読むと約37KB（トークンにすると12,000前後で、バイト数からの概算）になります。
そのため、点検用のスキルには、もう一方の規範は読まないと書き添えました。

## 使ってみて分かった注意点

数KB 以下の規範ファイルなら、抜き書きせずにそのまま取り込んで構いません[^small]。

読み物向けの規範を、作業報告や手順の記事に当てないことも決めました。
緩急の規範にある「`未回収の緊張を常に開いておく`」という条項は、結論を先に書くことと、事実と推測の区別を壊すからです。

条件付きの参照が実際に働くかは、まだ確かめていません。
条件を数えられる形にしても、条件に当たったかを判定するのは Claude なので、読まれる保証はありません。

## まとめ

10KB を超える規範ファイルを毎回効かせたいなら、全文を読ませるのではなく、効く条項だけを抜き書きして、必ず読まれる場所に置くと軽く済みます。
私の環境では、20,439 bytes を2,441 bytes にして CLAUDE.md に入れました。
手順は、適用の対象を分ける、ぶつかる条項を外す、置き先を確かめる、の3つです。
残りの本文は、数えられる条件を書いた参照から読ませます。
まず手元で一番大きなスキルのサイズを測り、10KB を超えていたら、手元の決まりとぶつかる条項を探すところから始めてみてください。

[^small]: 私の運用では、抜き書きするかの目安を10KB に置いています。
