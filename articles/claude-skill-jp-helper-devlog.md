Claudeデスクトップアプリの入力欄で `/` を押すと候補が出る。
手元の辞書に入れた分だけ数えると、コマンドは81個ある。
`/new` は `/clear` の別名で、`/fork` は `/branch` の別名で、`/checkpoint` は `/rewind` の別名だ。
名前を見ただけでどれを押すか決めきれない場面が続いたので、Claudeの隣に日本語の説明だけを出す常駐アプリを書いた。

macOSのオーバーレイアプリで、Electron 28とTypeScriptで動いている。
OSレベルでキー入力を拾い、前面のアプリがClaudeのときだけ `/` 以降の入力を追跡して、画面右下に候補を出す。

ただ、この入力を拾う部分には、リポジトリに残骸が一つ残っている。

## リポジトリに残っている二つ目の入力経路

`swift-helper/main.swift` が213行ある。
CGEventTapを直接張り、AXUIElementでClaudeのウィンドウ枠を取り、キー入力の変化をJSONにして標準出力へ流す設計だ。
ポップアップの表示位置も、Claudeウィンドウの右下端に合わせて計算するようになっている。

ところが `electron/src/main.ts` は、このヘルパーを一度も起動しない。
最初のコミットの時点で、main.tsはすでに `uiohook-napi` を require している。
Swift側の成果は、gitに履歴が残るより前に置き換えられていた。

置き換わった理由そのものは履歴に残っていないが、手放した経緯の一部は読める。
初日の2コミット目「Make app usable for others」で、コミットされていたヘルパーのビルド済みバイナリが削除され、メッセージにこう書かれている。

```
Remove x86_64-only Swift helper binary from git (main.ts uses uiohook-napi instead)
```

x86_64向けにコンパイルしたバイナリをリポジトリに置いたままにすると、Apple Silicon機でクローンした人の手元では実行できない。
自分の一台でしか動かしていないあいだ、この種の問題は表に出てこない。
同じコミットでREADMEも全面的に書き直され、必要な権限の記述が「アクセシビリティ」から「入力監視」に訂正されている。
公開の準備というより、他人の環境という条件を初めて計算に入れた回に見える。

## 前面アプリの判定に使えなかった osascript

**グローバルキーフック**はOS全体のキー入力を拾うので、Claudeがいない場所で押した `/` にも反応してしまう。
前面のアプリがClaudeかどうかを、キー入力とは別の手段で知る必要がある。

macOSでこれを聞く定番は osascript だが、architecture.mdには使わない理由が書いてある。
LaunchAgentから起動したコンテキストでは権限エラーになり、空文字が返る。
残った手段が `lsappinfo` で、`lsappinfo front` でASNを取り、`lsappinfo info -only bundleID <ASN>` の出力から `CFBundleIdentifier` を正規表現で抜いている。

外部コマンドを二回叩く判定なので、高頻度で回せば常駐アプリとしては重くなる。
main.tsのポーリングは、追跡中のテキストが空なら1秒、`/` の追跡が始まっていれば100ミリ秒と間隔を切り替えている。

それでも `/` が押された瞬間だけは、追跡を始める前に同期版で前面アプリを確かめている。
非同期の監視は最大1秒遅れるので、その1秒のあいだにアプリを切り替えて `/` を打たれると、Claude宛てでない入力で一覧が開いてしまう。
追跡の開始だけは遅れが許されない、という判断だと読める。

## フォーカスを奪わないポップアップ

ポップアップは `frame: false`、`transparent: true`、`focusable: false` のBrowserWindowで、`showInactive()` で出している。
入力中のClaudeからフォーカスを取り上げないための設定だ。
`setAlwaysOnTop(true, "pop-up-menu")` で最前面に置き、`setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })` で他のSpaceやフルスクリーンでも見えるようにしている。

隠すときはウィンドウを閉じず、`setOpacity(0)` と `setIgnoreMouseEvents(true)` で見えなくするだけにしている。
`/` を打つたびにウィンドウを作り直せば、その都度のレンダリングが表示の遅れとして出る。
要件に書かれている表示遅延の目標は100ミリ秒以内なので、常駐させて透明度だけ動かすほうが条件を満たしやすい。

これだけ設定しても、ポップアップがフォーカスを取ってしまう場合が残ったらしい。
main.tsは起動時に、`process.execPath` からたどった `Info.plist` を PlistBuddy に読ませて、自分自身のバンドルIDを取得している。
前面監視のたびに、前面アプリが自分だったらClaudeを呼び戻す、という後始末が入っている。

呼び戻しに使っているのは osascript だ。
前面判定からは外したコマンドが、こちらの用途では使われたままになっている。
理由はコードにもドキュメントにも書かれていない。

## 二度直したツールチップの幽霊枠

6月15日の17時21分、ホバーしていないのにツールチップの枠だけが見える不具合が修正されている。
`.tooltip.hidden` が `visibility: hidden` だったので、150ピクセルの領域が確保されたまま残っていた。
`display: none` に変えれば領域ごと消える。
その2分後、今度はツールチップが消えたときにリストが上へずれる問題を `justify-content: flex-end` で押さえている。

2分間で二つ、原因はCSSの箱の扱いだったことになる。

2日後の6月17日、まったく同じタイトルのコミットがもう一度入っている。

**原因はCSSではなかった。**
`hidePopup()` はウィンドウの opacity を 0 にするだけで、レンダラーには何も伝えていなかった。
DOM側のツールチップは `.hidden` が付かないまま残り、次に opacity が 1 に戻った瞬間、ホバーしていないのに前回の内容が見えていた。
修正は、`update-commands` を送る前に `hide-tooltip` をIPCで先に送り、レンダラー側の状態を戻してから表示すること。

症状が同じでも、CSSのボックスが残る話と、プロセスをまたいだ状態が残る話は別物だった。
ウィンドウを閉じずに透明度で隠す設計を選んだ時点で、メインプロセスの「隠した」とレンダラーの「隠れている」がずれる余地が生まれていた。

## 黙るキーフックへの手当て

`uiohook-napi` の下で動いているのはCGEventTapで、タップのコールバックが長引くとOSがそのタップを無効化する。
無効化されると、アプリは生きたままキー入力だけを受け取らなくなる。
常駐アプリとしては、落ちるより気づきにくい壊れ方だ。

コールバックを短く保つ側の対策は最初から入っている。
keydownハンドラは受け取ったイベントの必要な値だけをコピーして、実際の処理は `setImmediate` に逃がしている。
外部コマンドを叩く前面判定を、フックのコールバックの中で走らせないための形だ。

それでも無効化されたときの復帰が、6月26日に追加されている。
やり方は手荒で、`process.stderr.write` を差し替え、流れてくる文字列に `CGEventTap timeout` が含まれる回数を数えている。
5回続いたら `uIOhook.stop()` して1秒後に `start()` し、`start()` が例外を投げたら `app.quit()` する。

最後の一手が復帰として成り立つのは、KeepAliveを有効にしたLaunchAgentから起動している場合に限る。
コミットメッセージには `KeepAlive=true` と `ThrottleInterval=10s` に更新したとあるが、plistは `.gitignore` に入っているためリポジトリには残っていない。
READMEに載っているサンプルのplistは `KeepAlive` が `false` のままなので、READMEどおりに設定した人の手元では、この最後の一手はアプリが終了するだけで終わる。

同じコミットで `lastKeyEventAt` という変数が増えているが、値を書き込むだけで、どこからも読まれていない。
無音の時間で異常を判定する案が先にあって、stderrの監視に落ち着いた形跡に見える。

## コミットの大半を占める辞書の手入れ

19コミットのうち7コミットは、コードを一行も触らず `data/commands.json` だけを書き換えている。

初日に、公式ドキュメント（v2.1.170）に合わせた大きな改訂が入っている。
365行追加、221行削除。
`/vim` や `/pr-comments` のように提供が終わったものを落とし、当時ドキュメントにあったコマンドを足し、カテゴリを二つ増やしている。

その直後、claude.aiのセッションでは条件付きでしか出ない12コマンドが削除されている。
プラットフォーム固有だったり、特定の連携が入っていないと出てこないものだ。
辞書に載っていて実際には打てないコマンドは、説明を出す道具としては誤りに近い。

同じ日に、detailを短くして全コマンドに `例：` から始まる使用例が付けられている。
この区切り文字は表示側にも効いていて、popup.htmlは detail を `例：` で分割し、前半を説明文、後半を「使用例」欄に流し込んでいる。
JSONの中の文字列がそのままUIの構造を決めているので、辞書を書く側は区切り文字を守る必要がある。

6月22日には、ターミナル前提の9コマンドが落とされている。
`/tui`、`/terminal-setup`、`/diff` など、デスクトップアプリの画面では意味を持たないものだ。
90個から81個になった。

辞書は `dist` の外にあり、commands.tsが `__dirname/../../data/commands.json` を読むだけなので、編集してアプリを再起動すれば反映される。
再ビルドはいらない。
辞書の更新頻度がコードより高いことは、この構成を選んだ時点で当たっていた。

テストはJestとts-jestで、commands.tsに8件ある。
fsをモックし、`jest.resetModules()` を挟んでモジュール内に溜まる状態を毎回作り直す形で、前方一致、大文字小文字の無視、`/` 単独でのカテゴリ分け、読み込み失敗時に例外を投げないことを見ている。
キーフックとウィンドウ制御にテストはない。
権限、前面アプリ、常駐時間に依存する部分は、ユニットテストの外に置かれたままだ。

## 最後のコミットで消したもの

最新のコミットはコードを触っていない。
READMEのファイルツリーからem dashを消して `#` コメントに置き換え、箇条書きの途中のコロンを普通の文に直しただけだ。
タイトルは "Remove AI-flavored punctuation from README" となっている。

各コミットの Co-Authored-By を見ると、この一連の作業はClaudeと一緒に書かれている。
AIと書いた文章から、AIっぽい句読点を剥がす作業が最後に来ている。

いま `/` を押すと、右下に81個が7カテゴリで並ぶ。
`/checkpoint` にカーソルを乗せれば「/rewind のエイリアス」と出るので、`/rewind` を探し直さずに済む。
名前を見て手が止まる場面は減った。

`swift-helper/` は消していない。
213行のCGEventTapは、一度も呼ばれないままリポジトリに残っている。
消すのはいつでもできるので、まだ置いてある。
