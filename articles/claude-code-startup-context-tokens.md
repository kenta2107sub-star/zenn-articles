> 観測日: 2026-09-08、2026-09-11、2026-09-14 ／ 記事の作成: 2026-10-29（Claude Code 2.1.270、macOS 13.7.8）

Claude Code Desktop では、1ターン目の時点で、コンテキストに約7万トークンが載っていました。
総量はセッションの記録ファイルにある usage を足せば出て、内訳は同じファイルの attachment 行から分解できます。
ただし内訳の数字は文字数で、トークン数ではありません。

## 何が起きたか

2026-09-08 に、起動したばかりのセッションのコンテキストを調べ、約71,000トークンが載っているのを確かめました。
その後に測り直しても、Claude Code Desktop の 2.1.266 と Opus 5 の組み合わせでは、1ターン目の時点で約7万になりました。

~/.claude には、グローバルの指示文、知見メモの目次、自作のスキル40件の説明文、出力スタイルを置いています。
どれも毎回コンテキストに載るものです。
ところが、どれがどれだけ効いているのかは、設定ファイルを眺めるだけでは分かりません。

~/.claude の設定を減らすと、この7万はどこまで減るのか。
それを知るには、総量と内訳を別々に測る必要がありました。

## どう測ったか

総量は、セッションの記録ファイル（`~/.claude/projects/<フォルダ>/<セッション>.jsonl`）から取りました。
最初の assistant 行の usage にある3つの値を足します。

```
input_tokens + cache_creation_input_tokens + cache_read_input_tokens
```

2026-09-11 に、この方法で測った値は次のとおりです。
1ターン目の値なので、最初の指示文とフックが注入した分も含みます。

| モデル | バージョン | 1ターン目の総量 |
|---|---|---|
| Opus 5（Desktop） | 2.1.266（6セッション） | 70,040〜71,941 |
| Sonnet 5 | 2.1.261 | 57,393〜59,963 |
| Sonnet 5 | 2.1.255 | 81,071〜81,516 |
| Haiku 4.5 | 2.1.261 | 42,557 |

71,941 のセッションでは、cache_creation が 31,790、cache_read が 40,149 でした。

内訳は、同じ記録ファイルのうち `type` が `attachment` の行で見ました。

```bash
jq -r 'select(.type=="attachment") | [.attachment.type, (.attachment|tostring|length)] | @tsv'
```

出てくる数値は、attachment を JSON 文字列にしたときの長さです。
大きい順に並べると次のとおりでした。

- skill_listing 25,057
- instructions 13,152（グローバルの指示文と知見メモの目次）
- deferred_tools_delta 12,400
- mcp_instructions_delta 6,988
- output_style_instructions 2,890、agent_listing_delta 2,780、hook_success 1,252

2026-09-14 には、2.1.266 と Opus 5 の組み合わせで 69,002 でした。

## 原因

~/.claude 側で毎回載る分は、約14,100トークンと推定しました。
推定どおりなら、7万のうち ~/.claude の分は2割ほどです。
数え方は、英数字4文字を1トークン、ASCII 以外の文字1文字を1トークンとする概算です。
大きいのは、自作スキル40件の説明文（約5,610トークン）と知見メモの目次（約4,240トークン）でした。

約7万から約14,100を引いた残りの約5.5万は、ハーネス本体とアプリに組み込まれたツールだと考えています。
これは推測で、~/.claude からは削れない分だと見ています。

cache_read の 40,149 は、セッションをまたいで共通の前置きだと見ています。
これも推測です。

バージョンの差も効いていました。
同じ Sonnet 5 でも、2.1.255 と 2.1.261 では1ターン目の総量が2万以上違います。
同じモデルどうしでも、バージョンが変わると1〜2万の幅で動くので、比べるなら同じバージョンどうしで比べます。

測り方の側にも落とし穴がありました。
1つ目は、attachment 行を全部数えると膨らむことです。
セッションを再開すると、instructions などの attachment 行が記録ファイルの後ろに足されます。
2026-09-14 には、再開後のセッションを1ターン目に絞らずに数えたせいで、prompt_snapshot 166,649 などが混ざりました。

2つ目は、遅延ロードの MCP の数え方です。
遅延ロードの MCP は、ツールの名前しか載りません。
「1ツール約500トークン」の見積もりは、この場合には当てはまりません。

## どう直したか（直せなかったか）

測り方を2つに分けて固定しました。
総量は最初の assistant 行の usage で見て、内訳は attachment 行で見ます。
単語数に1.3を掛ける推定は、日本語には使えません。

内訳を数えるときは、最初の assistant 行より前の attachment 行に限ります。

```bash
jq -rs '(map(.type)|index("assistant")) as $i | .[:$i][] | select(.type=="attachment") | [.attachment.type, (.attachment|tostring|length)] | @tsv'
```

`-s` で全行を配列として読み、最初の assistant 行の位置で切ってから集計しています。
再開したセッションの記録ファイルでも、1ターン目の内訳だけが出ます。

~/.claude から削れるのは、スキルの説明文、知見メモの目次、出力スタイル、グローバルの指示文の4つです。
2026-09-14 にスキル23件を退避した後の skill_listing は 19,055 で、前の節で見た 25,057 より小さい値でした。

ただし、削れる分は全体のうち約14,100トークンにとどまります。
約5.5万の側は、~/.claude をいくら整理しても動かないと見ています。

## 残っている疑問

約5.5万がハーネス本体とアプリ組み込みのツールだという見立ては、確かめていません。
総量から ~/.claude 側の推定を引いた残りに、名前を付けただけです。

CLI で同じことを測ると、Desktop より小さくなるはずだと考えています。
CLI には、Desktop 固有のツールと、claude.ai から同期されるスキルが載らないからです。
これも未検証です。

cache_read の 40,149 がセッション共通の前置きかどうかも、推測のままです。
