売上の明細から「商品名を調べて書き写す」「担当者ごとに足し上げる」「条件に合う行だけ抜き出す」を手でやっていると、明細が増えるたびに同じ作業をやり直すことになります。
この3つは、XLOOKUP・UNIQUE（と SUMIFS）・FILTER で置き換えられます。
どれも Excel（Microsoft 365）と Google スプレッドシートの両方にある関数です。
ただし FILTER は、条件を2つ以上にするときの書き方が両者で違います。

## 例に使う表

シートを2つ用意します。

「商品」シート（A1:C5）

| | A | B | C |
|---|---|---|---|
| 1 | コード | 商品名 | 単価 |
| 2 | A01 | ボールペン | 120 |
| 3 | A02 | ノート | 180 |
| 4 | B01 | 付箋 | 250 |
| 5 | B02 | クリップ | 90 |

「明細」シート（A1:D9。E〜G列はこれから数式で埋めます）

| | A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|---|
| 1 | 日付 | 担当 | コード | 数量 | 商品名 | 単価 | 金額 |
| 2 | 10/1 | 佐藤 | A01 | 10 | | | |
| 3 | 10/1 | 鈴木 | B01 | 4 | | | |
| 4 | 10/2 | 佐藤 | A02 | 5 | | | |
| 5 | 10/2 | 田中 | A01 | 3 | | | |
| 6 | 10/3 | 鈴木 | A02 | 8 | | | |
| 7 | 10/3 | 佐藤 | B02 | 20 | | | |
| 8 | 10/4 | 田中 | C01 | 2 | | | |
| 9 | 10/4 | 鈴木 | A01 | 6 | | | |

8行目の「C01」は、わざと商品シートにないコードにしています。

## 1. 商品名と単価を引く（XLOOKUP）

明細シートの E2 と F2 に次の式を入れ、9行目までコピーします。

```
E2: =XLOOKUP(C2, 商品!$A$2:$A$5, 商品!$B$2:$B$5, "該当なし")
F2: =XLOOKUP(C2, 商品!$A$2:$A$5, 商品!$C$2:$C$5, 0)
G2: =D2*F2
```

XLOOKUP は「検索値・検索範囲・返す範囲・見つからないときの値」の順に書きます。
4つ目を省くと、見つからないときに `#N/A` が返ります（Excel の公式ヘルプの記載）。

結果は次のとおりです。

| 担当 | コード | 数量 | 商品名 | 単価 | 金額 |
|---|---|---|---|---|---|
| 佐藤 | A01 | 10 | ボールペン | 120 | 1,200 |
| 鈴木 | B01 | 4 | 付箋 | 250 | 1,000 |
| 佐藤 | A02 | 5 | ノート | 180 | 900 |
| 田中 | A01 | 3 | ボールペン | 120 | 360 |
| 鈴木 | A02 | 8 | ノート | 180 | 1,440 |
| 佐藤 | B02 | 20 | クリップ | 90 | 1,800 |
| 田中 | C01 | 2 | 該当なし | 0 | 0 |
| 鈴木 | A01 | 6 | ボールペン | 120 | 720 |

C01 の行は商品名が「該当なし」、金額が0になります。
単価を0にしておくと合計の式はエラーで止まりませんが、そのぶんコードの間違いを見落としやすくなります。
商品名の列で「該当なし」を探し、商品シートに足すか、コードの打ち間違いを直してください。

手で書き写す方法との違いは、商品シートの単価を直せば明細の金額がすべて変わることです。

## 2. 担当者の一覧を作り、担当者ごとに合計する（UNIQUE と SUMIFS）

I2 に次の式を1つだけ入れます。

```
I2: =UNIQUE(B2:B9)
```

I2 から下に「佐藤・鈴木・田中」の3行が出ます。
並びは明細に初めて出てきた順です（スプレッドシートの公式ヘルプの記載）。
結果が下のセルに広がるので、I3 より下は空けておきます。

J2 に合計の式を入れ、J4 までコピーします。

```
J2: =SUMIFS($G$2:$G$9, $B$2:$B$9, I2)
```

| 担当 | 合計 |
|---|---|
| 佐藤 | 3,900 |
| 鈴木 | 3,160 |
| 田中 | 360 |

明細に新しい担当者が増えたときは、UNIQUE の行も増えます。
ただし J 列の SUMIFS は自動では増えないので、行が増えたら下にコピーします。

## 3. 条件に合う行だけ抜き出す（FILTER）

「佐藤さんの、金額が1,000以上の行」を抜き出します。
ここで Excel と Google スプレッドシートの書き方が分かれます。

Excel では、条件を `*`（かけ算）でつないで1つの引数にします。
3つ目の引数に、1件もないときに出す値を書けます。

```
=FILTER(A2:G9, (B2:B9="佐藤")*(G2:G9>=1000), "なし")
```

Google スプレッドシートでは、条件を引数として並べます。
1件もないときの値を書く引数はありません。

```
=FILTER(A2:G9, B2:B9="佐藤", G2:G9>=1000)
```

Google スプレッドシートで確かめた結果は次の2行です（Excel の式も同じ行を返す書き方です）。

| 日付 | 担当 | コード | 数量 | 商品名 | 単価 | 金額 |
|---|---|---|---|---|---|---|
| 10/1 | 佐藤 | A01 | 10 | ボールペン | 120 | 1,200 |
| 10/3 | 佐藤 | B02 | 20 | クリップ | 90 | 1,800 |

条件に合う行が1件もないとき、Excel は3つ目の引数を省くと `#CALC!` を返します。
Google スプレッドシートは `#N/A` を返します（どちらも公式ヘルプの記載）。
空の結果がありうる表では、Excel は3つ目の引数を書き、スプレッドシートは `IFERROR` で包んでおくと、エラーの表示を避けられます。

## まとめ

| 手作業 | 置き換える関数 | 両者の違い |
|---|---|---|
| 商品名・単価を調べて書き写す | XLOOKUP | 同じ書き方で使える |
| 担当者を書き出して合計する | UNIQUE ＋ SUMIFS | 同じ書き方で使える |
| 条件に合う行を抜き出す | FILTER | 条件を2つ以上にするとき、Excel は `*` でつなぎ、スプレッドシートは引数を並べる |

3つとも、元の表を直せば結果が追いかけて変わります。
明細を足すたびに書き写していた作業は、範囲（`$B$2:$B$9` など）を広げておくだけになります。
